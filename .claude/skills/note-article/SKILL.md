# Note 記事作成ガイド

## 読者像
- 医療×テックに関心がある人
- プログラミング未経験〜初心者
- 音楽療法関係者
- 個人開発者
- ゆーのさんの成長を応援している人

### ターゲット（2方向・企画段階で意識する）
- **ICT系**：個人開発したい医療職。「非エンジニアの自分でも作れた」実話が刺さる
- **ミッドクライシス系**：閉塞感を感じてる医療職全般。「このままでいいのか」層

## Noteで求められること
- **共感**：「わかる！」と思ってもらえる失敗談や感情
- **ストーリー性**：なぜやったか・何が起きたかの流れ
- **わかりやすさ**：専門用語を自分の言葉で噛み砕く
- **親しみやすさ**：医療者としての視点・例えを活かす

## 執筆中

### タイトル設計の4つの問い

> **誰に × どんな価値 × どんな内容 × どう伝えるか**

| 問い | 具体例 |
|------|--------|
| ① 誰に向けた内容か？ | 副業初心者・ASD特性持ち・看護師 |
| ② どんな価値があるか？ | 3ヶ月で初収益・変われない理由がわかる |
| ③ どんな内容か？ | 音楽療法の基本・3ステップの実践 |
| ④ どう伝えるか？ | 体験談・ステップ解説・ビフォーアフター |

**避けたいタイトルパターン：**

| ❌ 避けたい例 | ⭕ 改善後 |
|-------------|---------|
| 最近思ったこと | 〇〇を始めて3ヶ月で気づいた、△△の考え方 |
| 開発日記 #1 | 看護師がReactでアプリ開発を始めた理由と最初の壁 |

### 構成の型（体験記事・開発日記向け）

```
背景・動機（なぜやろうとしたか）
  ↓
やってみた（何が起きたか・失敗も含めて）
  ↓
学んだこと
  ↓
次回予告
```

### 構成の型（読者を動かしたい・有料記事向け：PASONA法則）

| 要素 | 役割 | 文字目安 |
|---|---|---|
| P Problem | 読者の悩みを言語化。3秒で「これ自分のことだ」と思わせる | 200〜300字 |
| A Affinity | 共感。Yunoの体験・感情を生々しく書く | 300〜400字 |
| S Solution | 解決策・気づき・学び。根拠があれば添える | 400〜600字 |
| O Offer | 有料部分の予告・お試し提示（無料記事なら次の行動を提示） | 100〜200字 |
| N Narrowing Down | 期限・限定性（有料記事の場合） | 省略可 |
| A Action | 明確な指示。「スキ」「フォロー」「コメント」のどれか1つだけ促す | 50〜100字 |

**無料エリアの設計原則：**
- 冒頭3秒で「これ自分のことだ」→ 読者の悩みをピンポイントで言語化
- 無料だけで「この人プロだ」と思わせる → 出し惜しみしない
- 読者の熱量がMAXのところで有料ラインを引く
- 有料の先にある「変わった自分」を見せる

どちらの型を使うかは記事の目的次第：素朴な開発記録・体験共有なら前者、読者に行動（スキ・フォロー・購入）を明確に促したいなら後者。

## ファイル管理ルール

- **ZennのfrontmatterはNoteファイルに不要**。`title` / `emoji` / `type` / `topics` / `published` のfrontmatterブロックは削除する
- Zenn版とnote版は**タイトルが異なる場合がある**（Zenn版は技術寄り・note版は読者に刺さるタイトル）
- noteには独自のfrontmatter（`platform: note` / `published_date` / `tags`）を使うか、frontmatterなしでよい
